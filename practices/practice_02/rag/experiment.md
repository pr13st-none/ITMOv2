# RAG

- **Вопрос к источникам:** какие части ADR можно подтвердить локальными материалами курса и Практики 1, а какие являются нашим целевым решением?

## Разрешённые источники

| Файл или документ | Зачем нужен | Какой фрагмент используем |
|---|---|---|
| `../../practice_01/TRAINING_PR.diff` | Зафиксировать AS IS текущего кода | новый endpoint и `ReviewService.review` |
| `../../practice_01/README.md` | Зафиксировать контракт учебного помощника | «Задача помощника», хороший/плохой пример |
| `../../practice_01/problem.md` | Источник измеримых целей | evidence/check coverage, unsupported claims |
| `../../practice_01/product_management.md` | Источник use case и acceptance criteria | ≤3 risks, evidence, human decision |
| `../../practice_01/tests_*.md` | Проверить, что решение тестируемо | unit/integration/load/E2E сценарии |

## Запрос

```text
Ответь на вопрос об обоснованности ADR, используя только пять групп источников из таблицы.
Для каждого ключевого элемента решения укажи локальный файл и раздел, который его поддерживает.
Не используй web и не добавляй best practice как факт проекта.
Если элемент является нашим TO BE решением, так и пометь.
После ответа предложи компактную таблицу «Источник | Что подтверждает» для adr.md.
```

## Ответ со ссылками на источники

- AS IS цепочка подтверждается `TRAINING_PR.diff`: endpoint напрямую передаёт `payload["diff"]`, сервис формирует строковый prompt и возвращает `comment`.
- Требование ≤3 рисков, evidence/checks и human decision подтверждается `README.md` и отражено в `product_management.md`.
- Result Guard не существует в diff; это TO BE решение, поддерживающее метрики `problem.md` и негативный acceptance scenario.
- Минимальные полномочия AI следуют из запрета approve/merge/edit в README и Context Pack.
- Проверяемость bounded pipeline подтверждается тем, что его правила уже представлены в unit/integration/E2E спецификациях.

## Что изменили в исходном артефакте

- **Файл и раздел:** `practice_01/adr.md` — новый раздел «Источники решения».
- **Изменение:** ключевые claims ADR получили локальные ссылки; источник отделён от типа утверждения.
- **Как проверили ссылки:** каждый относительный путь существует; содержание вручную сопоставлено с claim; `make step1` проходит.
- **Что отклонили как неподтверждённое:** OWASP/внешние LLM security recommendations, конкретные SLA и инфраструктурные best practices — они не входят в разрешённый RAG-набор.
- **Чем отличается эффект:** RAG добавил provenance для архитектурных claims: полезность изменения определяется не стилем текста, а возможностью открыть локальный источник для каждого основания.
