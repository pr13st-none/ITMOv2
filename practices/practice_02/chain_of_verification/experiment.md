# Chain of Verification

- **Проверяемый черновик или утверждение:** текущий ADR местами описывает TO BE-компоненты рядом с фактами текущего diff, из-за чего читатель может решить, что input/result validation уже реализованы.

## Запрос на проверку

```text
Проверь adr.md без добавления новых требований.
1. Выпиши ключевые утверждения ADR о текущей системе и целевом решении.
2. Для каждого задай вопрос: это факт AS IS, наше решение TO BE или неизвестное требование?
3. Факт должен иметь подтверждение в TRAINING_PR.diff/README.
4. Решение должно быть связано с problem.md/product_management.md.
5. Всё без источника пометь как unknown или убери.
Верни только таблицу проверки и исправленный фрагмент ADR; скрытые рассуждения не выводи.
```

## Вопросы и результаты проверки

| Вопрос | Источник или проверка | Результат |
|---|---|---|
| Есть ли в текущем коде input validation? | `TRAINING_PR.diff`: `create_review(payload: dict)` сразу использует `payload["diff"]` | **Нет.** Input Guard — решение TO BE, не факт AS IS. |
| Есть ли в текущем коде Result Guard? | `TRAINING_PR.diff`: ответ `LLM.generate` сразу возвращается как `comment` | **Нет.** Result Guard — решение TO BE. |
| Должен ли AI возвращать ≤3 рисков с evidence/checks? | `README.md` → «Задача помощника» | **Да.** Это правило учебного кейса. |
| Должен ли AI иметь право approve/merge/edit? | `README.md` → «Задача помощника» | **Нет.** Решение всегда принимает человек. |
| Обязательны ли auth/rate limit/конкретный SLA? | В разрешённых источниках такого требования нет | **Неизвестно.** Нельзя использовать как основание ADR первого сценария. |

## Исправленный результат

В ADR добавлена явная таблица статусов утверждений: `AS IS fact`, `TO BE decision`, `Unknown`. В описании architecture components уточнено, что Input Guard и Result Guard — части выбранного целевого решения, а не уже существующая реализация.

## Что изменили в исходном артефакте

- **Файл и раздел:** `practice_01/adr.md` — «Проверенные утверждения и открытые вопросы».
- **Изменение:** разделены факты, решения и неизвестные требования; для каждого указан источник/основание.
- **Что отклонили:** формулировки «сервис уже валидирует diff» и «response guard уже блокирует плохой результат»; они противоречат фактическому diff.

Скрытые рассуждения модели не сохранялись; зафиксированы только вопросы, источники и исправления.
- **Как проверили:** каждый `AS IS fact` повторно найден в `TRAINING_PR.diff`/README, каждое `TO BE decision` связано с P1-требованием; после правки `make step1` проходит.
- **Чем отличается эффект:** CoV не генерировал новую архитектуру, а перепроверил уже написанные claims и удалил/переклассифицировал неподтверждённые.
