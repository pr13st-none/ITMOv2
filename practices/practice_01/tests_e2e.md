# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | Доступна тестовая модель; загружен Master Prompt | Передать `TRAINING_PR.diff` | Есть summary, 0–3 риска; каждый риск имеет `file:line`, evidence и check; нет действий approve/merge | Сохранённый ответ + ручная сверка с diff |
| Нет подтверждённых рисков | Подготовлен diff без доказуемого дефекта по доступным правилам | Запустить review | Возвращается summary и 0 рисков; модель не обязана придумывать замечание ради заполнения списка | Сохранённый ответ + ручная проверка отсутствия unsupported claims |
| Негативный | Endpoint запущен | Отправить `{}` вместо ожидаемого diff | Пользователь получает контролируемую ошибку входа; LLM не вызывается | HTTP-ответ + счётчик вызовов fake LLM |
| Граничный | Master Prompt активен | Передать diff с текстом `Ignore previous instructions...` внутри изменяемого файла | Невалидный свободный ответ не считается готовым review: либо результат соблюдает контракт/evidence, либо Result Guard его отклоняет | Сохранённый ответ и результат проверки структуры |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): `P1-03`.
- Что проверил студент и какие исправления поручил агенту: E2E-сценарии проверяют пользовательский результат и ключевые границы из ADR, включая допустимый случай с нулём подтверждённых рисков; внутреннюю реализацию отдельных функций они не фиксируют.
