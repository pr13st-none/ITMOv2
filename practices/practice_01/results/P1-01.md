# P1-01 — baseline: только diff и короткий запрос

Запрос: «Ниже diff учебного PR. Посмотри PR и найди проблемы.»

## Ответ baseline

В PR добавляется POST `/api/reviews`: обработчик достаёт `diff` из JSON, передаёт его в `ReviewService`, а тот формирует текстовый prompt и вызывает LLM.

Что выглядит проблемно:

1. В `app/api.py` используется `payload["diff"]` без проверки. Если ключа нет, обработчик упадёт с `KeyError`.
2. `payload` — обычный `dict`, поэтому контракт входа не описан Pydantic-моделью и тип `diff` не валидируется на границе API.
3. Пользовательский diff напрямую вставляется в prompt. Текст из diff может содержать инструкции для модели и влиять на результат review.
4. Вызов LLM никак не обёрнут обработкой исключений. Ошибка провайдера уйдёт наверх как серверная ошибка.
5. Нет ограничения размера diff, поэтому очень большой запрос может увеличить задержку и стоимость LLM.
6. Для нового endpoint не видно аутентификации и rate limit, поэтому им потенциально можно злоупотреблять.
7. Ответ состоит из одного поля `comment`; возможно, для code review лучше отдельные поля для summary и findings.
8. Вызов LLM синхронный, поэтому под нагрузкой endpoint может блокировать обработку запросов.

Стоит добавить валидацию входа, обработку ошибок, ограничение размера и более строгий prompt/формат ответа. Также нужны тесты на пустой JSON, неверный тип `diff`, исключение LLM и большой diff.
