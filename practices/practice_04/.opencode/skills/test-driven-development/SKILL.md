# Test-driven development

1. Сначала сформулируй одно наблюдаемое поведение.
2. Добавь минимальный тест и убедись, что он падает по ожидаемой причине.
3. Внеси минимальную правку, которая делает тест зелёным.
4. Запусти полный runner проекта.
5. Только после зелёного состояния можно рефакторить.

Не меняй тест только ради того, чтобы скрыть дефект реализации. Проверяй поведение, а не текст исходника.
