# Рефлексия

Больше всего пользы дал не сам MCP, а сочетание `AGENTS.md` и автоматической проверки после изменения. Правила снимают повторяющиеся уточнения из промпта, а hook сразу возвращает агенту результат тестов, поэтому не приходится отдельно вспоминать про runner после каждой правки.

TDD skill оказался полезен как ограничение порядка действий. Если сначала написать реализацию, маленькая модель легко подгоняет тест под уже получившийся код. С red → green проще увидеть, что тест проверяет именно нужное поведение.

MCP я специально сделал маленьким и read-only: он проверяет payload перед code review и использует ту же `check_payload`, что и обычный код. На корректном входе возвращается размер diff, на пустом — контролируемая ошибка `diff_required`. Так не появляется второй набор правил, который потом пришлось бы синхронизировать вручную.

Главное место, где всё равно пришлось контролировать агента вручную, — формулировка теста. Инструменты хорошо автоматизируют рутину, но сами по себе не гарантируют, что проверяется правильное поведение.
